2월부터 붙잡고 있던 watcher 를 README 로 정리했다. 410줄이 나왔다. 커밋 메시지는 "update readme" 였지만 실제로는 석 달 동안 만든 걸 처음으로 한 번에 훑어본 날이다.

watcher 는 GIS 분석 모듈을 대신 돌려 주는 중간 서버다. 가시권, 경로 탐색 같은 분석이 모듈마다 Docker 이미지로 따로 있고, API 서버는 "이 분석 돌려 줘" 라는 메시지만 큐에 넣는다. 나머지는 watcher 가 한다.

```
API 서버 → RabbitMQ → watcher → 분석 컨테이너 / HTTP 서비스
                         ↓
                     PostgreSQL (이력)
                         ↓
                    웹훅 → API 서버
```

## RabbitMQ 와 aio-pika

분석 종류마다 큐가 하나씩 있다. watcher 는 큐마다 컨슈머를 하나씩 띄운다. aio-pika 는 asyncio 위에서 도는 RabbitMQ 클라이언트라서, 컨슈머 열몇 개를 프로세스 하나에서 같이 돌릴 수 있다.

연결은 `connect_robust` 로 맺고, 그래도 끊기면 1초부터 30초까지 두 배씩 늘려 가며 다시 붙는다. 메시지는 `message.process()` 안에서 처리해서, 처리 중에 죽으면 ack 가 안 나가고 큐에 다시 남는다.

## aiodocker 로 형제 컨테이너 띄우기

watcher 자신도 컨테이너라서 `/var/run/docker.sock` 을 마운트해서 호스트의 Docker 를 직접 부른다. 컨테이너 안에서 Docker 를 또 띄우는 게 아니라 옆에 형제 컨테이너를 만드는 방식이다. aiodocker 로 create, start, wait, logs, delete 를 전부 비동기로 처리한다.

분석 컨테이너에 넘기는 값은 환경 변수로 준다. 순서가 중요했다. 결과 경로(`OUTPUT_PATH`)를 먼저 만들고, YAML 에 적힌 고정값, 메시지 본문에서 뽑은 값, 분석 종류 순서로 덮어쓴다. 같은 이름이 겹치면 나중 것이 이긴다.

## 설정은 YAML 하나로

큐 이름, 실행 방식, 이미지, 타임아웃, 결과 파일 이름, 볼륨, 동시 처리 수를 `watcher.yml` 에 적는다. 분석이 하나 늘면 코드는 안 고치고 YAML 에 블록 하나만 추가하면 된다. YAML 은 읽기 전용으로 마운트해 둬서 설정만 바꿨을 땐 `docker compose restart` 면 끝난다.

실행 방식은 두 가지다.
- container: 컨테이너 실행 → 끝날 때까지 대기 → 결과 파일 확인 → tiff 면 COG 로 변환
- service: 이미 떠 있는 분석 서버에 HTTP POST 를 보내고 응답을 기다림

## 상태와 에러 코드

요청이 들어오면 PostgreSQL(asyncpg)에 이력을 `10`(진행 중)으로 넣고, 끝나면 `20`(성공) 이나 `99`(실패)로 바꾼 뒤 웹훅을 보낸다. 웹훅은 httpx 로 보내고 실패하면 세 번까지 다시 보낸다.

실패 이유를 API 쪽에서 구분할 수 있게 에러 코드를 나눴다. `D` 는 Docker 쪽(종료 코드, 타임아웃), `W` 는 watcher 쪽(결과 파일 없음, COG 변환 실패), `L` 은 분석 모듈 쪽이다. `L` 은 모듈이 따로 알려 주지 않아서 컨테이너 로그에서 `MemoryError`, `No such file or directory`, `Permission denied` 같은 문자열을 찾아서 붙인다. 깔끔하진 않은데, 모듈마다 고치는 것보다 빨랐다.

## 막혔던 것

- 동시 처리. 큐마다 `asyncio.Semaphore` 와 `prefetch_count` 를 같은 값으로 맞춰서 조절한다. 경로 탐색만 5로 올렸고 나머지는 1이다. 6 이상으로 올리면 메모리가 확 튀었다. 분석 컨테이너 메모리를 1초 간격으로 `container.stats()` 로 찍어서 요청별 JSON 리포트로 남기게 해 뒀고, 그 리포트를 보고 5에서 멈췄다.
- 타임아웃. `container.wait()` 를 `asyncio.wait_for` 로 감싸서, 오래 걸리는 변환 작업은 YAML 에서 따로 1시간까지 늘렸다.
- 저장소. 분석 데이터가 NAS 에 있어서 NFS 로 마운트한다. 재부팅 뒤 마운트가 풀려 있으면 분석이 전부 "파일 없음" 으로 떨어진다. fstab 에 `hard` 옵션으로 등록하고, 재부팅 뒤 확인할 순서(NAS → Docker → watcher → RabbitMQ 연결)를 README 에 적어 뒀다.
- 로그. 처음엔 크기 기준(`RotatingFileHandler`)으로 돌렸는데, 3월에 날짜 기준(`TimedRotatingFileHandler`)으로 바꾸고 gzip 으로 묶어 30일만 남기게 했다. 장애 났던 날짜로 찾는 일이 대부분이라 이쪽이 맞았다.

## 남은 것

웹훅을 받는 쪽이 자체 서명 인증서를 쓰면 httpx 검증에서 막힐 수 있다. 아직 그런 환경은 없어서 README 에 메모만 해 뒀다.
