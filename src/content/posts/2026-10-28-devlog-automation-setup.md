블로그를 Astro 로 다시 만들면서 욕심이 하나 생겼다. 매일 커밋한 걸 모아서 일지 초안을 자동으로 받고 싶었다. 직접 쓰려면 결국 안 쓰게 되니까.

하루 만에 끝날 줄 알았는데 생각보다 여러 번 구조를 바꿨다.

## 수집: GitHub REST API

처음엔 GitHub API 로 그날 커밋을 모으는 스크립트부터 짰다.

- `/users/{owner}/repos` 로 저장소를 받고 `pushed_at` 이 그날 이후인 것만 남긴다.
- 저장소마다 브랜치를 돌면서 `/repos/{repo}/commits?sha=브랜치&author=...&since=...&until=...` 로 커밋을 가져온다. 기본 브랜치만 보면 develop 에서 한 작업이 다 빠져서 브랜치를 전부 돌게 했다.
- 커밋마다 바뀐 파일 목록과 추가/삭제 줄 수만 가져온다. 코드(patch)는 안 가져온다.

여기서 처음 막힌 게 author 필터다. `author` 에 계정 이름을 넣으면 그 계정에 연결된 이메일로 한 커밋만 잡힌다. 회사 메일로 커밋한 건 계정에 연결이 안 돼 있어서 하나도 안 나왔다. 이메일을 따로 받아서 author 를 여러 번 조회하게 바꿨다.

## 민감정보 거르기

공개 블로그에 올라가는 거라 이게 제일 신경 쓰였다. 정규식으로 GitHub 토큰, API 키, JWT, DB 접속 문자열, `password=` 같은 할당, 이메일, IP, URL 을 지운다. `.env`, `.pem`, 서비스 계정 json 같은 파일은 목록에서 아예 뺀다.

`\bpassword` 로 잡으면 `DB_PASSWORD=` 가 안 걸리더라. `_` 도 단어 문자라서 `\b` 경계가 안 생긴다. 앞뒤에 `\w*` 를 붙여서 고쳤다. 이런 게 또 있을까 봐 가짜 키를 잔뜩 넣은 시험 파일을 만들어서 워크플로가 돌 때마다 먼저 돌린다.

글이 다 써진 뒤에도 같은 필터를 한 번 더 통과시킨다.

## 글쓰기는 API 대신 구독으로

처음엔 Actions 에서 Claude API 를 부르게 했다. 근데 작업한 날마다 돈이 나가는 게 걸려서 Claude Code 예약 작업으로 바꿨다. 이미 내고 있는 구독 안에서 돈다.

PC 예약 작업은 PC 가 켜져 있어야 해서, 결국 클라우드 루틴으로 옮겼다.

## 막혔던 것

클라우드로 옮기고 나서 수집이 계속 실패했다.

1. 세션에 있는 `GITHUB_TOKEN` 이 GitHub API 에서 401 이 났다. git 용 토큰이라 API 에는 안 먹는 것 같다.
2. 토큰을 빼니 이번엔 시간당 60회 한도에 걸렸다. Node 의 `fetch` 는 `HTTPS_PROXY` 를 안 보고 바로 나가서 공용 IP 한도를 같이 쓰고 있었다. `curl` 은 프록시를 타서 한도가 넉넉했다. 프록시가 있으면 curl 로 부르게 바꿨다.
3. 그래도 403. 세션이 루틴에 연결한 저장소에만 묶여 있어서 그 밖의 API 경로는 아예 막혀 있었다.

3번은 코드로 풀 수 있는 게 아니었다. 그래서 역할을 나눴다.

- 수집은 비공개 저장소의 GitHub Actions 가 한다. 공개 저장소는 기본 토큰으로, 비공개는 읽기 전용 fine-grained 토큰으로 읽는다. 결과는 그 비공개 저장소에만 쌓는다.
- 클라우드 루틴은 그 저장소 파일만 읽어서 글을 쓴다.

비공개 저장소 커밋 메시지가 공개 저장소에 남으면 안 돼서 수집 결과 위치를 따로 둔 거다. 비공개 저장소는 글에서도 이름을 가리고 파일은 확장자만 남긴다.

## 보류함과 관리 페이지

처음엔 초안을 PR 로 올렸는데, 블로그 저장소가 공개라서 PR 을 열면 공개 전인 글도 누구나 읽을 수 있었다. 그래서 초안은 비공개 저장소의 `drafts/` 에 쌓고, 블로그에 `/admin/` 을 만들어서 거기서 골라 공개하게 했다.

GitHub Pages 는 서버가 없어서 로그인을 따로 만들 수가 없다. 그래서 GitHub 권한을 그대로 빌려 썼다. 관리 페이지에 fine-grained 토큰을 한 번 넣으면 `GET /user` 로 토큰 주인이 나인지 확인하고, 그 토큰으로 비공개 저장소에서 초안을 읽는다. 공개 버튼을 누르면 Git Data API 로 블로그 저장소에 커밋 하나를 만들고(tree → commit → ref 이동), 보류함에서는 지운다. 여러 개를 골라도 커밋은 하나라 배포도 한 번만 돈다. 토큰은 그 브라우저 localStorage 에만 둔다.

## 남은 것

예전 커밋도 같은 방식으로 저장소·기간별로 묶어서 글로 만들어 보류함에 넣어 뒀다. 하나씩 읽어 보고 공개하는 중이다.
